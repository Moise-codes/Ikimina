# Ikimina API

Backend API for *ibimina* (Rwandan community savings and lending groups). FastAPI +
PostgreSQL 16 + Redis 7, written in Python 3.12.

This guide covers local development. The design document lives at
[`../docs/ikimina-v2-design.md`](../docs/ikimina-v2-design.md).

## Requirements

- Python 3.12+ (the Docker image and CI pin 3.12)
- Docker and Docker Compose (for PostgreSQL and Redis)
- `venv` + `pip` only — do **not** use `uv` or other package managers

## Setup

```bash
# From the repository root.

# 1. Virtual environment
python3 -m venv .venv
source .venv/bin/activate

# 2. Dependencies (runtime + dev tooling)
pip install -r backend/requirements-dev.txt

# 3. Environment file: copy the template and fill in strong secrets
cp .env.example .env
#    Generate the two secrets with:
#      python -c "import secrets;print(secrets.token_urlsafe(48))"
#      python -c "import base64,os;print(base64.urlsafe_b64encode(os.urandom(32)).decode())"

# 4. Start PostgreSQL and Redis (bound to 127.0.0.1, credentials from .env)
docker compose up -d

# 5. Apply database migrations
cd backend
alembic upgrade head
```

The application **fails fast** at startup if a required setting is missing or weak
(for example a `SECRET_KEY` shorter than 32 characters or a `*` CORS origin with
credentials). Configuration is validated in
[`app/core/config.py`](app/core/config.py).

## Run

```bash
# From backend/, with the virtual environment active:
uvicorn app.main:app --reload

# Production-style (Gunicorn supervising Uvicorn workers):
gunicorn app.main:app --config gunicorn.conf.py
```

- Liveness probe: `GET /health`
- Readiness probe: `GET /ready` (checks PostgreSQL and Redis; returns 503 when a
  dependency is unreachable)
- Interactive docs (`/docs`, `/redoc`, `/openapi.json`) are served only in
  `local`/`development`. They are disabled in `staging`/`production` unless
  `DOCS_ENABLED=true`.

You can also run the whole stack in containers:

```bash
# From the repository root.
docker compose up -d --build api   # runs migrations, then serves on $API_PORT
docker compose ps                  # check health
```

## Test

```bash
cd backend
pytest                 # runs the suite with the coverage gate (see pyproject.toml)
pytest -m unit         # fast, no external services
pytest -m integration  # needs PostgreSQL and Redis (docker compose up -d)
```

Tests read configuration from the environment; [`tests/conftest.py`](tests/conftest.py)
provides deterministic values and derives a dedicated test database
(`POSTGRES_TEST_DB`) so the development data is never touched.

## Migrate

Migrations use Alembic. The database URL always comes from application settings,
never from `alembic.ini`.

```bash
cd backend
alembic upgrade head                              # apply all migrations
alembic revision --autogenerate -m "add x table"  # create a new migration
alembic downgrade -1                              # roll back one revision
alembic history                                   # list revisions
```

All tables inherit the shared constraint naming convention defined in
[`app/core/database.py`](app/core/database.py), so autogenerated constraint names
are stable.

## Quality and security checks

Run these before committing — the same commands run in CI:

```bash
cd backend
ruff check .            # lint (includes bandit-style S rules)
ruff format --check .   # formatting
mypy app                # strict static types
pip-audit -r requirements.txt   # dependency vulnerability scan
bandit -r app -q        # static security scan
```

`pip` and `pyproject.toml` pin exact versions (`==`) for reproducible builds;
every dependency has a one-line justification where it is declared in
[`requirements.txt`](requirements.txt).

## Layout

```
backend/
├── app/
│   ├── api/            # routers (health probes, versioned API aggregate)
│   ├── core/           # config, database, redis, errors, middleware
│   └── main.py         # application factory and wiring
├── migrations/         # Alembic environment and versioned migrations
├── tests/              # unit / integration / contract / concurrency tests
├── Dockerfile          # multi-stage, non-root runtime image
├── gunicorn.conf.py    # production process configuration
└── requirements*.txt   # pinned runtime and dev dependencies
```
